# 美术馆文创权利链与开发协作服务

面向公立美术馆短期特展的文创开发场景：从作品与权利主体开始记录可核验的
授权链，产品提案逐项核验权利条件，设计送审、学术审核、法务确认、合作方
承诺汇合后冻结投产版本；授权变更、撤回、到期自动触发停售、库存处置与
待结版税任务，全程留有可核验的审计记录。

## 模块地图

| 模块 | 职责 |
| --- | --- |
| `domain.py` | 最初的最小授权契约（保留不动，其半开区间约定被全系统沿用） |
| `errors.py` | 领域异常：权限、核验、状态、权利不满足、审批未汇合 |
| `catalog.py` | 作品与权利主体登记；入藏只记录保管事实，**入藏不等于授权** |
| `licensing.py` | 授权台账：可核验来源（合同编号+文件摘要）、用途/地域/渠道/数量/版税/有效期；登记、变更、撤回全是追加事件，历史版本不可改写 |
| `proposal.py` | 产品提案：引用多件作品，逐项声明用途、地域、渠道、数量、销售窗口 |
| `evaluation.py` | 逐项权利核验：对作品的**每一个**权利主体逐一比对，给出具体失败原因 |
| `review.py` | 设计版本（每次送审一个新版本）、三方审批汇合、不可变的投产版本快照 |
| `override.py` | 紧急人工放行：限定时效、责任到人，只能豁免流程环节 |
| `impact.py` | 影响处置任务：停售、库存处置、待结版税 |
| `audit.py` | 追加式审计日志，哈希链防篡改，`verify()` 可校验完整性 |
| `service.py` | 编排层：角色权限、冻结硬门槛、权利影响、到期提醒、销售登记、版税对账 |
| `interfaces.py` | 隔离接口：`InternalInterface`（馆方）与 `PartnerInterface`（外部合作方） |

## 核心不变量

1. **未经许可的方案必须始终停在生产之前。** 冻结投产前逐项核验权利条件，
   紧急放行也不能豁免；审批再齐，权利不满足就抛出 `RightsNotSatisfied`，
   拦截本身也记入审计。
2. **已发生事实不可改写。** 授权事件链、冻结的投产版本、审计日志都只追加；
   授权变更、撤回、到期触发的是处置任务，而不是修改历史。
3. **审批针对当前设计版本。** 审批中替换设计即产生新版本，旧版本上的
   学术/法务/合作方确认不再计入汇合，必须重新审批。
4. **接口隔离。** 外部合作方只能看到并操作本机构参与的提案（送审设计、
   合作方承诺、查看状态），触不到登记、冻结、放行、对账与审计；服务层
   仍按角色与机构双重校验，绕过门面同样被拦截。

## 角色

`registrar`（权利登记）、`curator`（策展/提案/冻结）、`academic`（学术审核）、
`legal`（法务确认）、`partner`（外部合作方）、`supply`（供应链）、
`finance`（版税结算）、`admin`（馆方管理，紧急放行责任人）。

## 运行

```bash
python -m unittest discover -s tests -v
```

当前为纯内存实现的领域服务核心（无外部依赖，Python ≥ 3.12），所有写操作
显式传入时间以便审计与复核；持久化与 Web 接入可在 `service.py` 的
仓储边界上扩展。
